thinca 27日 02:59:42 Slack
files が gh-pages に置けない問題、ひとまず解消しました。
pages に置くファイルには 10GB のリミットがあり、それを越えてしまっていたためデプロイができない状態でした。
主原因は添付ファイルで、これだけで 8GB 近く消費していました。
ただ、よくよく考えると、これらのファイルは pages にデプロイできていないだけで、リポジトリ上には push できており、GitHub のサイト上からも参照ができます。
そして添付ファイル類は html から参照されているに過ぎません。
と言うわけで、files は pages には含めず、外部 CDN を経由して GitHub 上のリポジトリのファイルを直接参照すればいいじゃない。と言う感じにしました。
最初は raw.githubusercontent.com を使おうかと思ったんですが、こいつは content-type を application/octet-stream で送ってくるので画像ファイルをクリックすると直接ダウンロードになってしまってアレだったので、
https://www.jsdelivr.com/ さんを使わせてもらうことにしました。…こんな用途に使っていいんだろうか。ちょっとわかってないのでもしもっといい選択肢をご存知の方がいたら教えてください 🙏

GitHub 27日 21:59:48 Slack
<https://github.com/vim-jp/slacklog-generator/issues/168|#168 CDN が大きなファイルを扱えない場合がある>
例えば jsDelivr の場合、20MB 以上のファイルを扱うことができません。

https://github.com/jsdelivr/jsdelivr#restrictions

raw.githubusercontent.com の場合はデータの取得はできますが、Content-Type が application/octet-stream になっているため、画像を単独で開こうとした場合に表示ではなくローカルへの保存になってしまったりしてあまり嬉しくない場合があります。

また、jsDelivr の場合は access-control-allow-origin 等のヘッダがありますが、githubusercontent にはありません。
例えば今後、 SPA にしてログデータの JSON を取ってくるような仕組みにする場合は githubusercontent は使えないことになります。
